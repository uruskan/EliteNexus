# Elite Nexus — user guide

Unzip the release and run `EliteNexus.exe`. It finds your journal folder automatically
(Saved Games\Frontier Developments\Elite Dangerous), reads your whole history in well under a second, then follows
the game live. Run it before or after the game — order doesn't matter. On Linux, run `./EliteNexus`: it finds the
journals in the game's Proton prefix (see [Linux](#linux)). On a Mac, open `Elite Nexus.app`: it finds them in the
game's NotProton, CrossOver or Whisky prefix (see [macOS](#macos)).

## The window

The **sidebar** on the left lists every page; on narrow windows it shrinks to icons (hover for names). At its foot
is your commander: name, current system and a fuel gauge (hover for ship and situation, click for the Dashboard).

Each page has a large title, and the **toolbar** at the top right shows, left to right: your credits, the live
market feed (**EDDN n/min**: click it for the market database), uploads sent this session (once you enable a service;
amber = a service is paused or rejecting, click for details), **Pause EDDN / Resume EDDN** when you share with EDDN
(market prices are only sent when you undock, so pausing while docked keeps a market you just found to yourself), and
**Live / Offline** (Live = the game is writing events). The round button next to it turns the window into a small
always-on-top **HUD** for a second monitor or the edge of your screen (location, fuel, next star and whether it's
scoopable, exobiology sampling radar, surface mining radar, system value, last alerts). "Full view" switches back.

Alerts appear as banners at the top right and are spoken if you enable voice.

## Simple first, everything still there

Each page shows the one thing you usually need, with smart defaults (your current system, your ship's jump range and
landing pad). Every advanced setting the original tools offer, such as Spansh's routing algorithm, neutron/injection
choices or market filters, is one click away under **› Options**.

Only the cockpit's own lights change: stations, carriers, planets and the HUD stay as they are. **Install the dimmer** first says exactly what happens, then downloads 3Dmigoto 1.4.9 (4.7 MB) from its official GitHub release, checks it against pinned checksums and puts d3d11.dll, d3dcompiler_47.dll, d3dx.ini, EliteNexus-3Dmigoto.json and a ShaderFixes folder next to EliteDangerous64.exe, then asks you to **calibrate** once: start the game, get into your cockpit somewhere quiet (docked or in open space), quit to the desktop. For that one session the game records the shaders it loads (about 21 MB, deleted afterwards) and runs without the dimmer; when it closes, Elite Nexus finds the light shader among them and keeps a fix for exactly that shader, named by its fingerprint (**Finish calibration** does it by hand, **Cancel** stops). The HUD shaders for "Keep hostile red…" are found in the same run. In the game 3Dmigoto only swaps those shaders: everything else, including shaders the game adds later (new ships, new carriers), is left alone. The tab shows when and for which game build it was calibrated; after a game update it says so and asks you to **Calibrate again**, because a changed light shader no longer matches (the dimmer is then simply off; the game is unaffected). Installs from Elite Nexus 0.3.0 ran a pattern inside the game on every shader it loaded, which crashed the game near the newer fleet carriers: the tab says so (and, while its hook is in place, a notice at start) and **Update and calibrate** replaces it (and puts back a d3d11.dll that was renamed to switch the hook off). **Remove** takes out exactly those files (any that changed since are left in place), the calibration and its fixes, and the files 3Dmigoto made. The same install is the graphics hook HUD colours uses to keep hostile red, friendly green and shield blue, so Remove switches that off too. Frame captures and exported shaders left in the game folder from setting 3Dmigoto up (`FrameAnalysis-…`, `ShaderCache`) are shown with their size, and **Delete them** removes them; the dimmer doesn't use them. Settings saved here apply the next time the game starts; in the game, **F9** switches the dimmer on and off, **F10** steps the light kept (0, 15, 35, 60, 100 %) and **F11** the reach (5, 8, 12 m), while the game window is in front. They work only without Shift, Ctrl or Alt held. The game gets every press of these keys too (Elite Nexus can't hold one back, and never changes your controls): if the control presets the game uses bind one of them on its own, the tab names the action, because pressing the key then does both, and if it can't read those presets it says so instead of guessing. The fixes are made on your PC from your own game and never leave it. It can't run alongside EDHM or another 3Dmigoto mod (the tab says so if one is there), and Frontier tolerates such mods without having approved them. On Linux it is untested: Proton brings its own d3d11.dll (DXVK) and may skip the one in the game folder, so if calibrating finds no shaders, add `WINEDLLOVERRIDES="d3d11,d3dcompiler_47=n,b" %command%` to Elite Dangerous's launch options in Steam (Properties › General). |

## Voice

Alerts are spoken through Windows speech (on Linux through speech-dispatcher's `spd-say`, which most desktop
distributions include, or `espeak-ng` / `espeak` without it; with none of them alerts are shown, not spoken; on macOS
through the system's `say`). Settings › **Test voice** says which one spoke, or why none could. Choose the minimum
priority in Settings:
* **Critical** — hull critical, ship destroyed.
* **High** — Earth-like/water/ammonia/terraformable/high-value bodies, motherlodes, analysis complete, massacre
  mission done, fuel low with a non-scoopable star next, interdiction.
* **Normal** — biological signals, sample 1 logged (+ distance to move), codex entries, carrier jump scheduled.
* **Low** — arrival announcements, discovery-scan body counts, system fully scanned.

## Data & privacy

Everything lives in `nexus-data\` next to the executable (settings, galaxy database, logs). Nothing is uploaded
unless you enable it in Accounts & sync; when you do, only live game data is sent (never your history, credits or
cargo), following each service's published rules.

On Linux, when the folder next to the program can't be written to, data goes to `~/.local/share/EliteNexus` (or
`$XDG_DATA_HOME/EliteNexus`). On macOS, `Elite Nexus.app` keeps its data in `~/Library/Application Support/EliteNexus`
(never inside the app, so replacing the app keeps it).

Your settings are in `settings.json` in the data folder. If that file can't be read (typically after editing it by
hand: JSON writes every backslash twice, so a network folder is `"\\\\MAINPC\\Elite Dangerous"`), Elite Nexus never
starts over silently. It keeps the file as it was (`settings-unreadable-<date>.json`, next to it), keeps every
setting that still reads (from a file that isn't JSON at all, the EDSM and Inara keys, and the Ask key with the
service it belongs to; uploads stay off until you switch them on again) and says so in a banner above every page. A
file it can't open at all, say one another program is holding, isn't saved over until the next start. Settings ›
Journal › **Browse…** sets folders without editing the file.

If Elite Nexus closes unexpectedly, it writes where to `crash.log` in the data folder (Settings › About › Data folder
› **Open**), and the next start says it didn't close normally. `nexus.log` there shows what it was doing. Neither file
is sent anywhere: attaching them to a GitHub issue or a Frontier Forums post helps fix the problem. A journal entry
Elite Nexus can't handle is skipped (and listed under Settings › Journal) instead of stopping it from following the
game. Start it from a folder you unzipped it into: run from inside the zip, Windows unpacks it to a new temporary
folder each time, settings and database included, and Elite Nexus says so.

## Linux

Elite Nexus runs natively on 64-bit Linux: unpack `EliteNexus-…-linux-x64.tar.gz` anywhere and run `./EliteNexus`.
The game itself runs under Proton (Steam) or Wine (Lutris, Heroic), and writes its journals and settings inside that
Wine prefix, in the same folders as on Windows; Elite Nexus reads them there. The Linux build is new: it is built and
tested on Ubuntu, and a commander has confirmed it with the game under Proton (Nobara Linux 44 on Wayland: the journals
were found by themselves, Exploration and Exobiology work). HUD colours and Cockpit lights haven't been confirmed there
yet. Reports are collected in GitHub issue #3 (github.com/uruskan/EliteNexus/issues/3).

* **Journal folder**: found automatically in the game's Proton prefix in every Steam library (native, Flatpak and
  Snap Steam): `steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite
  Dangerous`. Then in Lutris's (`~/Games/<game>`) and Heroic's (`~/Games/Heroic/Prefixes/default/<game>`) usual
  prefixes and `~/.wine`. For any other prefix, enter the folder under **Settings › Journal › Custom journal folder**.
* **Bindings, HUD colours, Glare and exposure** use the game's Options folder in the same prefix
  (`…/drive_c/users/<name>/AppData/Local/Frontier Developments/Elite Dangerous/Options`), so they work as on Windows.
* **The game folder** (built-in control presets, Cockpit lights) is found in your Steam libraries, and in Program
  Files inside the game's prefix for a Frontier or Epic launcher run under Wine. Anywhere else, set it under
  **Settings › Game**.
* **Cockpit lights** and **Keep hostile red, friendly green and shield blue** use 3Dmigoto, which is untested under
  Proton. If calibrating finds no shaders, add `WINEDLLOVERRIDES="d3d11,d3dcompiler_47=n,b" %command%` to the
  game's launch options in Steam.
* **App menu**: Settings › About › **App menu** › **Add** puts Elite Nexus and its icon in your desktop's app menu
  (`~/.local/share/applications/elite-nexus.desktop` and icons under `~/.local/share/icons`, no root needed); Wayland
  docks then show its icon too. From a terminal: `./EliteNexus --install-desktop` (`--uninstall-desktop` takes it
  out). Move the program and the row says the menu still starts the old copy, with **Point it here**.
* **Voice** uses `spd-say` (speech-dispatcher), else `espeak-ng` or `espeak`. Under **Test voice**, Settings says
  which one spoke, that none is installed, or what went wrong (speech-dispatcher also needs an output module, such as
  `speech-dispatcher-espeak-ng` on Fedora and Nobara). **API keys** aren't encrypted (Linux has no DPAPI); the settings
  file that holds them is readable only by your user account.
* The window draws with Vulkan or OpenGL, on X11 or Wayland. On Wayland the compact HUD can't keep itself above
  other windows (Wayland doesn't let apps do that): start Elite Nexus as `WAYLAND_DISPLAY= ./EliteNexus` to run it
  through XWayland, where it can.

## macOS

Elite Nexus runs natively on macOS (Apple Silicon and Intel) as `Elite Nexus.app`, next to Elite Dangerous running
under NotProton (Steam Play for the macOS Steam client), CrossOver or Whisky. On a Mac with Apple Silicon, download
`EliteNexus-…-macos-arm64.zip` from the latest release, unzip it and drag `Elite Nexus.app` to Applications. The app
isn't notarized by Apple (that needs a paid developer account), so the first time you open it macOS refuses: open
System Settings › Privacy & Security and click **Open Anyway** next to Elite Nexus, once. On an Intel Mac, build it
from the source with `tools/macos/build-app.sh --install` (it needs Xcode's Command Line Tools and Rust), which puts
the app in Applications. The macOS build is new and hasn't been tried by us with every way of running the game.

* **Journal folder**: found automatically in the game's prefix in every Steam library, which is where NotProton keeps
  it, the same layout as Proton's: `~/Library/Application Support/Steam/steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite Dangerous`.
  Then in CrossOver's bottles (`~/Library/Application Support/CrossOver/Bottles/<bottle>`) and `~/.wine`, and only
  when none of those has one, in Whisky's bottles (they sit in Whisky's own container, so macOS asks once whether
  Elite Nexus may look there). For any other prefix (Sikarugir, a Wineskin wrapper), enter the folder under
  **Settings › Journal › Custom journal folder**.
* **Bindings, HUD colours, Glare and exposure** use the game's Options folder in the same prefix, as on Linux.
* **The game folder** (built-in control presets, Cockpit lights) is found in your Steam libraries
  (`~/Library/Application Support/Steam/steamapps/common/Elite Dangerous`) and in Program Files inside the prefix.
* **Cockpit lights** and **Keep hostile red, friendly green and shield blue** use 3Dmigoto, which is untested on
  macOS: CrossOver runs Direct3D 11 through D3DMetal or DXVK. If calibrating finds no shaders, add
  `WINEDLLOVERRIDES="d3d11,d3dcompiler_47=n,b" %command%` to the game's launch options in Steam; if it still finds
  none, the hook can't run there, and **Remove** takes it out again.
* **Voice** uses the system's `say`, in the system voice chosen in System Settings › Accessibility › Spoken
  Content. **API keys** aren't encrypted (there's no DPAPI); the settings file that holds them is readable only by
  your user account.
* The window draws with Metal. The compact HUD stays above other windows, but macOS gives a full-screen app a Space
  of its own, where other apps' windows don't show: run the game in a window, or put the compact HUD on a second
  display.
